# 学习模型与 UI 设计基线

状态：已确认，实施前基线
确认日期：2026-08-21
适用范围：后续信息架构、内容、交互和视觉改动

## 1. 一句话定义

> 这不是一个把 AI 教给学生的网站；它陪学生从真实问题出发，借助 AI 取得可验证成果，并逐步长出自己的工作流。

AI 是扩展个人能力边界的杠杆，不是替人决定目标、承担风险或替人判断结果的万能答案。

## 2. 要培养的能力复利循环

用户不需要先学完一套教程，再开始解决问题。学习应发生在真实问题中，并留下下一次可以复用的资产：

```text
兴趣或真实问题
  -> 把目标、现象和证据说清楚
  -> 借助 AI 排查并先得到小范围计划
  -> 执行一个有边界的动作
  -> 用可观察证据验收成果
  -> 留下一条规则、Markdown、模板或复盘
  -> 下一次类似问题更快、更可靠
```

网站在这个循环中只提供当前一步所需的最小支架。它不应穷举所有故障、预装一整套复杂工具，或把用户推进抽象概念中。

### 四个用户问题

任何页面、任务和主按钮都必须服务于至少一个问题：

1. 我为什么对这件事感兴趣，或我现在想解决什么？
2. 我如何借助 AI 把问题描述清楚、排查并行动？
3. 我用什么证据确认结果真的有效？
4. 我该留下什么，让下一次同类问题更轻松？

如果一个区块不能推进其中任一步，它不应占据首屏或主要视觉位置。

## 3. 内容与信息架构原则

### 3.0 前期固定基线，后期生长引导

“生长性指导”不等于取消指引和规范。学习路径分为两个阶段：

1. 前期先建立少量、明确的共同基础。当前首要确认是用户是否已经安装好 Claude Code、Codex 和 WorkBuddy。这里采用自我确认，不要求用户为了证明状态而额外运行命令；如果用户尚未安装或不确定，Claude Code 提供官方安装说明，Codex 与 WorkBuddy 提供卡兹克的对应图文供核对。社区图文必须保留来源类型与核查日期。
2. 基础就绪后，指导重心转向真实问题中的学习、生长和个人方法沉淀。用户不再被固定教程牵着走，而是在目标、边界、证据和复盘循环中逐渐形成自己的工作流。

固定基线必须尽可能短，只处理后续学习无法绕过的前置条件；不得把进阶概念、完整工具生态或一套“标准答案工作流”继续堆进入门门槛。

### 3.1 前台是一条连续路径，三层路线是后台组织方式

入门、项目、工作流三个层级仍用于组织内容与判断难度，但不要求新手先理解或选择自己的“层级”。新手的前台入口应从以下任一状态开始：

- 我有一个想做的小目标。
- 我遇到了一个具体问题。
- 我想看一个能激发兴趣的真实方向。

完成一次任务后，系统再根据用户已经留下的证据与沉淀，引导到项目约束、验证、规则、Agent 或自动化等下一层内容。

### 3.2 渐进披露，先行动后解释

每个页面默认只展示：

- 当前目标：这一步要完成什么。
- 一个主动作：现在点哪里、问什么或做什么。
- 完成证据：看到什么才算完成。
- 下一步：完成后去哪里。

“为什么这样做”、完整来源、更多示例、进阶工具和术语放在可展开的次级层。首屏不能同时出现多条同等优先级路径、大段解释和长资源列表。

### 3.3 遇到错误时，直接使用已有 AI 能力

本站不维护排障数据库，也不提供站内排障助手。用户遇到错误时，直接把目标、报错原文或截图交给 Codex、豆包或手边可用的 AI：

```text
我的目标是……
实际出现的是……
我已经尝试了……
证据是……（报错原文、截图、相关代码/文件结构、系统与工具版本）
请先判断原因与最小修改范围，再给我验证步骤；不要直接重写无关部分。
```

这段方法只作为可迁移的学习提示，不扩展成错误分类、解决步骤或站内问答产品。产品不重复建设通用 AI 已经能够高效完成的诊断能力。

### 3.4 小目标任务是主练习，不是长篇教程

首批任务应被设计为任务卡，而不是完整教程文章。每张卡仅包含：

- 小目标：15–45 分钟能完成的真实产出。
- 边界：允许改什么、不做什么、是否应使用测试目录或备份。
- 交付物：一个页面、文档、测试结果、变更说明或脚本输出。
- 验收证据：至少三条可观察、可复查的标准。
- 复盘提示：本次最值得带到下一次的一条规则。

候选首批任务方向：学习计划单页、作业截止日期工具、课程自测 Quiz、课程项目 README、简单函数测试、Git diff 变更说明。涉及真实成绩、实验数据或已有项目大范围改动的任务，放在学生已具备备份、匿名化和验证习惯之后。

### 3.5 来源不是资源墙，而是行动的配套信息

来源展示采用三层聚合：

1. 官方资料：产品事实、安装、权限、安全与变更的唯一事实依据。
2. 大型 AI / 开发者社区：发现真实痛点、讨论议题和项目灵感。
3. 个人创作者站点：观察个人工作流、失败经验和实践方法。

本站自己的校园经验仍使用 `Personal Note`，不要和第三层外部创作者混为一类。每条外部来源还要记录证据用途、直接链接、核查日期、适用范围和审核状态。社区与创作者不构成产品事实依据。

推荐的每周机制应被做成行动，不是订阅流：3 分钟选问题、5 分钟核对官方边界、15 分钟小实践、7 分钟写下结果与可复用规则。

## 4. 页面呈现契约

### 首页

- 首屏之前先询问 Claude Code、Codex 与 WorkBuddy 是否已经安装好；“没有 / 不确定”时才展开 Claude Code 官方说明与另外两篇对应图文。
- 首屏优先回答“你现在想解决什么”，并只给一个默认主动作。
- 路线图展示进度和可选深度，不能让三层入口成为第一次使用的决策负担。
- 将“当前目标、完成证据、下一步”作为每个主要模块的固定锚点。

### 任务页

- 先显示小目标、预计时间、交付物与验收标准。
- 将 AI 提问结构与执行边界放在动手前。
- 完成后引导保存自己的复盘或规则，而不是只跳回列表。

### 遇到错误时

- 页面只提示用户保留目标、报错原文或截图，并交给可用的 AI。
- 不建立排障分类、问题卡、详情页或站内 AI 助手。
- 提醒用户不要在求助内容中暴露密钥、密码、Cookie 等敏感信息。

### 来源与更新页

- 默认按来源层级和站点聚合，而非平铺同一官网的多个文档链接。
- 页面显示“这个来源适合做什么”，具体文档在需要时再展开。
- 来源页不取代每条事实旁的具体来源链接。

## 5. 已确认的 UI 设计基线

### 5.1 视觉意图

界面应保持安静、可信、有呼吸感的文档产品气质：它是陪学生思考和行动的工作台，不是高刺激的营销页、复杂仪表盘或教程信息墙。

当前视觉参考：

- `ui/post-assets/home-roadmap.png`
- `ui/post-assets/tool-selection.png`
- `ui/ai-programming-onboarding-navigator/src/index.css`

### 5.2 不可破坏的视觉要素

- 纸张底色、低透明度噪点与细点阵网格的轻质感。
- 克制的 `paper / ink / sage / clay / oat` 色板；黑色仅用于主文字、主按钮和少量高优先级状态。
- 衬线标题、无衬线正文、等宽代码的三套字体层级。
- 大留白、细边框、柔和阴影、圆角大卡片和胶囊形主按钮。
- 编辑式的标题排版：大号、紧凑字距、必要时使用低对比斜体副句。
- 轻量、缓慢、可打断的位移动效；动效只能服务层级和反馈，不能制造注意力竞争。
- 顶部极简导航：路线图、首次实践、来源与更新，以及一个明确 CTA；移动端通过菜单收纳次级入口。

实现层面的现有设计 token 以 `src/index.css` 为准：

```text
paper #fbfaf8  |  ink #121110  |  clay #e8e4e0
oat   #f3f0ec  |  sage #4f5547
serif Libre Baskerville | sans Inter | mono JetBrains Mono
```

### 5.3 允许的改动

- 调整首屏的信息顺序、主按钮文案和任务卡结构，以降低认知负担。
- 将来源链接从平铺列表改成按站点聚合、按需展开。
- 在已有卡片、时间线与留白体系内加入“目标 / 证据 / 下一步 / 复盘”组件。
- 为移动端收紧间距、字号与卡片密度，同时保持排版层级与触控可用性。
- 在不改变色彩性格的前提下，修正低对比文字以满足可读性。

### 5.4 禁止的改动

- 不得整体改成高饱和渐变、紫蓝科技风、游戏化界面或 SaaS 仪表盘。
- 不得用密集卡片瀑布流、过多标签、过度图标或并列 CTA 替代内容层级。
- 不得移除纸张感、衬线标题、克制色板、大留白和主按钮的视觉角色。
- 不得为了加入新功能而把首页改成资源目录、工具对比表或大段教程。
- 不得把所有进阶术语、Skill、MCP、Agent 预设为新手第一步。

## 6. 改版前后验收

每次涉及 UI 或信息架构的改动，至少检查：

- 首屏在 10 秒内能看出当前可做的一件事，且只有一个主 CTA。
- 页面能指出完成证据与下一步，而不是只提供说明。
- 事实性文字仍能追溯到具体官方来源，社区/创作者材料有清晰标签。
- 1440px 桌面和 390px 移动宽度下，标题、正文、按钮和卡片均可读、可点击且不溢出。
- 新组件继续使用既有色板、字体、圆角、边框、阴影和动效语法。
- 使用截图与现有参考图进行视觉回归；任何明显偏离必须在改动说明中解释原因。

## 7. 实施顺序

1. 先调整来源数据模型与来源页聚合方式，不改变现有视觉语言。
2. 将首页从“选层级”收束为“选择当前真实问题或小目标”，三层改为渐进深度。
3. 将首次实践页改成少量任务卡，并加入通用求助模板、验收证据与复盘沉淀。
4. 移除排障数据库与站内助手，只保留“把完整信息交给可用 AI”的通用方法。
5. 增加每周 30 分钟机制和个人工作流沉淀入口。

任何实际 UI 实现开始前，先针对该步骤写清用户目标、页面主动作、完成证据、数据来源和视觉回归范围。
