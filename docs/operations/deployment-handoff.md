# Deployment Handoff

Last updated: 2026-08-21

## Current release state

- Product redesign is complete and validated locally.
- The site is a React + Vite single-page application.
- There is no application server, embedded AI assistant, or site-owned feedback API.
- Maintainer contact points to <https://github.com/BallCard>.
- User feedback opens a prefilled issue in <https://github.com/BallCard/ai-coding-onboarding-navigator/issues>.
- The update announcement is dismissible; only that preference is stored in the visitor's browser.

## Feedback behavior after deployment

The current feedback feature works on static hosting and Sites without a database. Submission happens on GitHub, so the site does not display a false success state or pretend to persist data.

Tradeoff: visitors need a GitHub account. If real usage shows that this blocks campus users, a later release can add a native form backed by Sites D1. Do not use browser storage as the source of truth for centrally collected feedback.

## Hosting paths

### Existing static/Vercel path

`vercel.json` contains the SPA rewrite needed for direct navigation to nested routes. The production output is generated by `npm run build`.

### Sites path

The repository has not yet been linked to a Sites project and does not contain `.openai/hosting.json`. At deployment time, use the Sites workflow for this existing Vite application. Let the workflow create and persist the project metadata and adapt the build output; do not hand-write a project id.

The current release needs neither D1 nor R2. If native feedback is added later, declare D1 at that time and commit its schema and migrations with the feature.

## Pre-publish checklist

1. Confirm the deployment source is the intended branch and commit.
2. Run the content contract, TypeScript check, production build, and route smoke test.
3. Review the homepage at 1440px and 390px.
4. Confirm Claude Code, Codex, and WorkBuddy installation links.
5. Confirm GitHub contact and feedback links.
6. Test the update announcement's route link, feedback link, and close action.
7. Confirm nested routes open directly rather than returning a hosting 404.
8. Publish privately first when the hosting flow offers that choice, then review the deployed URL before widening access.

## Known non-blocking items

- The production bundle still triggers Vite's chunk-size warning; route-level code splitting can be handled in a later performance pass.
- The feedback flow is intentionally GitHub-based rather than anonymous or native.
